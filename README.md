# ตื่นเช้า (TUEN_CHAO) — ระบบสั่งเครื่องดื่มผ่าน LINE

LIFF (หน้าสั่ง) → Google Apps Script (API) → Google Sheet (หลังร้าน) → LINE Messaging API (ใบเสร็จ/แจ้งเตือน)

```
docs/            หน้า LIFF (โฮสต์บน GitHub Pages)
  index.html     หน้าสั่งเครื่องดื่ม
  config.js      ใส่ LIFF_ID และ GAS_URL
  demo.js        ข้อมูลตัวอย่าง (ใช้เมื่อ GAS_URL ว่าง หรือเปิด ?demo)
gas/             โค้ด Apps Script (ผูกกับ Google Sheet)
  Code.gs        API: init / checkCode / order / pushReceipt + ทริกเกอร์แก้สถานะ
  Line.gs        ตรวจ ID token, ส่งข้อความ, webhook, Flex ใบเสร็จ
  Data.gs        อ่าน/เขียนชีต, ตั้งค่า, รอบส่ง
  Setup.gs       setup() สร้างชีต + ข้อมูลเริ่มต้น, testLine()
```

## ความสามารถ

- เมนู / ราคา / รอบส่ง / สถานที่ / ความหวาน / ท็อปปิ้ง แก้ได้ในชีต ไม่ต้องแก้โค้ด
- ปิดรับก่อนถึงรอบตาม `cutoffMinutes`, จำกัดแก้วต่อรอบ, วันหยุดประจำสัปดาห์, ปุ่มปิดร้านชั่วคราว
- ลูกค้ายืนยันตัวตนด้วย LINE ID token — เซิร์ฟเวอร์คำนวณราคาใหม่ทั้งหมด ไม่เชื่อยอดจากหน้าเว็บ
- โค้ดส่วนลด (เฉพาะลูกค้าใหม่ / จำกัดจำนวนครั้ง), ออเดอร์แรกต้องโอนบัญชีกสิกร
- บัตรสะสมแต้ม ครบ `stampGoal` แก้วได้สิทธิ์แก้วฟรี (ฟรีแก้วที่ราคาตั้งต้นแพงที่สุด)
- ส่งใบเสร็จ Flex พร้อมข้อมูลบัญชีกสิกรและ QR ของร้าน (ถ้ามี), แจ้งร้านเมื่อมีออเดอร์ใหม่
- ลูกค้าส่งรูปสลิปในแชท → ระบบตอบรับและเปลี่ยนสถานะเป็น `รอตรวจสอบ`
- ร้านติ๊ก `paid` หรือเปลี่ยนสถานะในชีต → ลูกค้าได้ข้อความตั้งแต่ `กำลังทำ` ถึง `กำลังส่ง` และข้อความขอบคุณเมื่อ `ส่งแล้ว`
- จำเบอร์โทรและสถานที่ส่งล่าสุดของลูกค้า

ลองดูหน้าตาโดยไม่ต้องตั้งค่าอะไร: เปิด `docs/index.html` ผ่านเว็บเซิร์ฟเวอร์ใดก็ได้ (เช่น `npx http-server docs`) — ถ้า `GAS_URL` ว่างจะเข้าโหมดตัวอย่างเอง

## ติดตั้ง

### 1. Google Sheet + Apps Script

1. สร้าง Google Sheet ใหม่ → เมนู **ส่วนขยาย › Apps Script**
2. สร้างไฟล์ `Code.gs`, `Line.gs`, `Data.gs`, `Setup.gs` แล้ววางโค้ดจากโฟลเดอร์ `gas/`
   (หรือใช้ [clasp](https://github.com/google/clasp): `clasp clone <scriptId> --rootDir gas` แล้ว `clasp push`)
3. **การตั้งค่าโปรเจกต์** → เขตเวลา `(GMT+07:00) Bangkok`
4. เลือกฟังก์ชัน `setup` → **เรียกใช้** → อนุญาตสิทธิ์
   จะได้ชีต `Menu`, `Settings`, `Codes`, `Customers`, `Orders` พร้อมเมนูตัวอย่าง

### 2. LINE

ทั้งสองแชนเนลต้องอยู่ใต้ **Provider เดียวกัน** ไม่อย่างนั้น userId จะไม่ตรงกัน และส่งข้อความหาลูกค้าไม่ได้

1. **Messaging API channel** (คือ LINE OA ของร้าน) → แท็บ Messaging API → ออก **Channel access token (long-lived)**
2. **LINE Login channel** → จด **Channel ID** (แท็บ Basic settings)
   - แท็บ LIFF → Add
     - Size: `Full`
     - Endpoint URL: URL ของ GitHub Pages จากขั้นที่ 4 เช่น `https://<user>.github.io/<repo>/`
     - Scopes: ✅ `openid` ✅ `profile` ✅ `chat_message.write`
     - Add friend option: **On (Aggressive)** — ลูกค้าต้องเป็นเพื่อนกับ OA ถึงจะได้รับใบเสร็จ
   - จด **LIFF ID**
3. Apps Script → **การตั้งค่าโปรเจกต์ › Script properties** เพิ่ม
   | Property | ค่า |
   |---|---|
   | `LINE_CHANNEL_ACCESS_TOKEN` | token จากข้อ 1 |
   | `LINE_LOGIN_CHANNEL_ID` | Channel ID จากข้อ 2 |

### 3. Deploy Apps Script เป็น Web app

**ทำให้ใช้งานได้ › การทำให้ใช้งานได้รายการใหม่ › เว็บแอป**
- ดำเนินการในฐานะ: **ฉัน**
- ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน**

คัดลอก URL ที่ลงท้ายด้วย `/exec`

> แก้โค้ดครั้งต่อไป ให้ไปที่ **จัดการการทำให้ใช้งานได้ › แก้ไข › เวอร์ชันใหม่** URL จะยังเหมือนเดิม
> (ถ้ากด "การทำให้ใช้งานได้รายการใหม่" จะได้ URL ใหม่ ต้องแก้ config.js ตาม)

### 4. หน้า LIFF บน GitHub Pages

1. ใส่ค่าใน `docs/config.js`
   ```js
   LIFF_ID: "2001234567-AbCdEfGh",
   GAS_URL: "https://script.google.com/macros/s/XXXX/exec",
   ```
2. push ขึ้น GitHub → Settings › Pages → Source: `main` / `/docs`
3. นำ URL ที่ได้ไปใส่เป็น Endpoint URL ของ LIFF (ขั้นที่ 2)

### 5. ให้ลูกค้าเข้ามาสั่ง

ใช้ลิงก์ `https://liff.line.me/<LIFF_ID>` ใส่ใน Rich menu ของ OA (LINE OA Manager › Rich menu › Action: Link) หรือส่งในแชท/โพสต์

### 6. ทดสอบ

- Apps Script → เรียกใช้ `testLine` → ดูใน Log ว่า bot info ตอบ 200
- เปิดลิงก์ LIFF ในมือถือ → สั่ง 1 แก้ว → ต้องเห็นแถวใหม่ในชีต `Orders` และได้ใบเสร็จในแชท

## ใช้งานประจำวัน (ฝั่งร้าน)

| อยากทำ | แก้ตรงไหน |
|---|---|
| ปิดร้านชั่วคราว | `Settings › acceptingOrders` = `FALSE` (ข้อความที่ลูกค้าเห็นแก้ที่ `closedMessage`) — เปิดใหม่ใส่ `TRUE` |
| หยุดเป็นวัน ๆ | `Settings › closedDates` เช่น `2026-10-13,2026-10-20` |
| หยุดทุกสัปดาห์ | `Settings › closedWeekdays` เช่น `0` = ทุกวันอาทิตย์ |
| เวลาเปิดรับของวันนี้ | `Settings › openTime` เช่น `07:00` |
| เมนูหมด | `Menu › active` เอาติ๊กออก (เมนูยังแสดง แต่เป็นสีเทา "ไม่พร้อมให้บริการ") |
| ปิดระดับความหวานบางระดับของเมนู | `Menu › sweetOff` เช่น `0%` หรือหลายระดับคั่นด้วย `\|` |
| เปลี่ยนทั้งเมนูเป็นชุดใน `Setup.gs` | Apps Script → เรียกใช้ `replaceMenu` (ลบเมนูเดิมในชีตทั้งหมด) |
| เพิ่มเมนู | เพิ่มแถวใน `Menu` (`id` ห้ามซ้ำ, `colors` = `สี:ความสูง%` คั่นด้วย `\|`, หรือใส่ `imageUrl` เป็นรูป https) |
| เรียงขายดี | `Menu › bestRank` 1, 2, 3, 4 (ว่าง = ไม่ขึ้นในขายดี) |
| ตั้งบัญชีรับเงิน | `Settings › bankName`, `bankAccountName`, `bankAccountNo` และ `bankQrUrl` (QR ไม่บังคับ แต่ต้องเป็นลิงก์รูป `https`) |
| ได้สลิปและยอดถูกต้อง | `Orders › paid` ติ๊ก ✓ → ระบบเปลี่ยนเป็น `กำลังทำ` และแจ้งลูกค้า |
| ทำเครื่องดื่มเสร็จ | `Orders › status` → `พร้อมส่ง` |
| เริ่มออกไปส่ง | `Orders › status` → `กำลังส่ง` |
| ส่งถึงลูกค้าแล้ว | `Orders › status` → `ส่งแล้ว` (ลูกค้าได้รับข้อความขอบคุณ) |
| ยกเลิกออเดอร์ | `Orders › status` → `ยกเลิก` (คืนแต้ม/สิทธิ์แก้วฟรี/โค้ดให้ลูกค้าอัตโนมัติ) |
| สร้างโค้ดส่วนลด | เพิ่มแถวใน `Codes` (ช่องโค้ดเปิดด้วย `Settings › enableCodes` = `TRUE`) — ดูคอลัมน์ด้านล่าง |
| เปิดบัตรสะสมแต้ม | `Settings › enableStamps` = `TRUE` (ตอนปิดจะไม่สะสมแต้ม) |
| เปิด/ปิดตัวเลือกเพิ่ม (แยกน้ำแข็ง, เพิ่มช็อต ฯลฯ) | `Settings › extras` (ชื่อ=ราคา) และ `extrasOff` (ตัวที่ขึ้นสีเทา "ไม่พร้อมให้บริการ") |
| รอบส่ง | `Settings › slots` (เช่น `06:30,07:30,08:30,09:30`), `cutoffMinutes` (`30` = สั่งก่อน 7:00 ส่ง 7:30) และ `preorderOnlySlots` (รอบที่ต้องสั่งล่วงหน้า เช่น `06:30`) |
| ส่งทันทีไม่ต้องเลือกรอบ (วันนี้) | `Settings › asapToday` = `TRUE` แล้วใช้ `todayLastOrder` เป็นเวลาปิดรับ |
| โปรเปิดร้าน | แถว `OPEN10` ในชีต `Codes` — ใส่ `startDate` / `endDate` เป็นสัปดาห์แรก (เช่น `2026-10-12` / `2026-10-18`) |

| ข้อความอื่นภาษาอังกฤษ | `Settings › shopSubEn`, `closedMessageEn`, `locationsEn`, `dropOptionsEn`, `extrasEn` (รายการต้องเรียงตามลำดับเดียวกับภาษาไทย) |

### ภาษาไทย / อังกฤษ

ลูกค้ากดปุ่ม `EN` / `ไทย` มุมขวาบนเพื่อสลับภาษา (ครั้งแรกระบบเลือกตามภาษาของแอป LINE) ใบเสร็จและข้อความแจ้งสถานะจะส่งเป็นภาษาที่ลูกค้าใช้ตอนสั่ง
ส่วนร้านเห็นออเดอร์ในชีตและข้อความแจ้งเตือนเป็นภาษาไทยเสมอ (คอลัมน์ `Orders › lang` บอกว่าลูกค้าใช้ภาษาอะไร)

อย่าเปลี่ยนชื่อหัวคอลัมน์ในแถวแรก (สลับลำดับคอลัมน์ได้ หรือเพิ่มคอลัมน์ของตัวเองต่อท้ายได้)

### แจ้งเตือนออเดอร์ใหม่เข้า LINE ร้าน

ใส่ userId ของเจ้าของร้าน (ดูได้ที่ Messaging API channel › Basic settings › **Your user ID**) หรือ groupId ของกลุ่มพนักงานใน `Settings › adminTo`
ถ้าตั้ง webhook แล้ว (ด้านล่าง) พิมพ์ `ไอดี` ในแชท/กลุ่มที่มีบอท บอทจะตอบ id กลับมาให้

## ประหยัดโควตาข้อความ (ไม่บังคับ)

ข้อความแบบ push (ใบเสร็จ, แจ้งร้าน และแจ้งสถานะ) นับรวมในโควตารายเดือนของ LINE OA
แพ็กเกจฟรีได้ประมาณ 300 ข้อความ/เดือน (ตรวจสอบตัวเลขล่าสุดใน OA Manager) ส่วนข้อความแบบ **reply ไม่นับโควตา**

ถ้าเปลี่ยน `Settings › receiptMode` เป็น `reply`:
1. หน้า LIFF จะส่งข้อความ `ยืนยันออเดอร์ ORD-…` ในนามลูกค้า แล้วบอทตอบกลับด้วยใบเสร็จ (ฟรี)
2. ถ้าส่งไม่ได้ (เช่น ลูกค้าเปิดนอกแอป LINE) ระบบจะ push ให้แทนโดยอัตโนมัติ

ต้องตั้งค่า webhook เพื่อให้รับรูปสลิปและใช้ `receiptMode = reply` ได้:
- Messaging API channel › **Webhook URL** = URL `/exec` เดียวกัน › เปิด **Use webhook**
  (ปุ่ม Verify อาจขึ้น error เพราะ Apps Script ตอบแบบ redirect แต่ข้อความยังเข้ามาปกติ)
- LINE OA Manager › การตอบกลับ › ปิด **ข้อความตอบกลับอัตโนมัติ**

เมื่อลูกค้าส่งรูปสลิป บอทจะตอบว่าได้รับแล้วและตั้งออเดอร์ล่าสุดที่ยังไม่ชำระเป็น `รอตรวจสอบ`
ข้อความอื่นที่บอทตอบได้: `แต้ม` (ดูบัตรสะสมแต้ม), `ไอดี` (ดู userId/groupId)

## หมายเหตุด้านความปลอดภัย

- ทุก request จากหน้า LIFF แนบ ID token ซึ่ง Apps Script ส่งไปตรวจกับ LINE ก่อนทุกครั้ง (cache ไว้จนกว่า token หมดอายุ)
- ราคา ส่วนลด รอบส่ง และสิทธิ์ต่าง ๆ คำนวณใหม่ฝั่งเซิร์ฟเวอร์ทั้งหมด
- ข้อความจากลูกค้าที่ขึ้นต้นด้วย `=` จะถูกเก็บเป็นตัวอักษร ไม่กลายเป็นสูตรในชีต
- Apps Script อ่าน header ของ request ไม่ได้ จึงตรวจ `X-Line-Signature` ของ webhook ไม่ได้ การรับสลิปจึงตอบกลับผ่าน replyToken ก่อนเสมอ
  และจะเปลี่ยนสถานะเป็น `รอตรวจสอบ` หลัง LINE ยอมรับ replyToken ของ event จริงเท่านั้น
- ระบบไม่ส่งเลขบัญชีหรือยอดเงินไปสร้าง QR กับบริการภายนอก ถ้าต้องการแสดง QR ให้ร้านอัปโหลดรูปเองแล้วใส่ URL ใน `bankQrUrl`
